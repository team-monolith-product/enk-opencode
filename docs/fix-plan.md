# 외부 연동 — 값 전달 방식에 대한 개발 검토 결과

> 대상: `enk-plan-md/03-planning/product/2026-07-27_참가자-API키-등록관리-기획.md` (v2.5)

## 문제

지금 설계는 **값을 저장하는 것**까지만 보장하고, 그 값이 **앱에 도달하는 것**은 보장하지 않는다. §7.1이 "vite 계열은 읽는다"를 전제로 쓰였는데 짓다는 그 계열을 강제하지 않기 때문이다.

그래서 저장은 성공하고 반영은 조용히 실패한다. 관리 화면은 "3분 전 등록", AI는 "연결됐어요", 실제 앱은 값 없음. 셋 다 거짓말을 안 하는데 결과가 틀리고 참가자는 원인을 찾을 수 없다.

해결은 **`.env`를 자동으로 읽는 환경을 하나로 고정하고 거기에 전부 맞추는 것**이다. 지금은 "읽는지, 어디서 읽는지, 브라우저까지 가는지, 우선순위, 반영 방식" 다섯 가지를 AI가 매번 추론으로 정한다. 고정하면 전부 상수가 되고, AI 지침이 "판단하라"에서 "이 규칙을 따르라"로 바뀐다.

---

## 기획 결정이 필요한 것 (3건)

### 1. §7.2 프록시를 해결책 후보에서 내린다

우리가 요청을 대신 보내며 키를 붙여주는 방식은, 대상이 단순한 HTTP 호출이고 키를 정해진 자리에 넣기만 하면 되는 경우에만 성립한다. 서명을 매번 계산하는 방식(HMAC 등), 토큰 갱신과 OAuth, 스트리밍·웹소켓, 서비스 제공 라이브러리가 인증을 자체적으로 쥐는 경우는 감쌀 수 없다.

핵심은 개별 항목이 아니라 **대응 범위가 열려 있다**는 점이다. 참가자가 어떤 서비스를 쓸지 우리가 정하지 않으므로 무엇이 등장할지 미리 알 수 없다. 특정 서비스를 위한 개별 대책은 될 수 있어도 기능 전체가 딛고 설 기반은 못 된다.

### 2. 제품 약속을 다시 정한다

환경을 고정하면 값은 앱에 확실히 도달한다. 대신 화면에서 쓰는 값은 이름에 접두사를 붙여 브라우저로 올라가므로 방문자가 볼 수 있다. §5 셋째로 이미 적혀 있는 한계이고, 프록시를 뺀 이상 남는다.

> **값이 앱에 도달하는 것은 보장한다. 화면에서 쓰는 값이 방문자에게 보이는 것은 막지 않는다.**

이 구분을 문서에 박아주면 좋겠다. 그러면 두 가지가 따라온다.

- **§3.4 카피 가드레일에 한 줄 추가.** 현재 문구("값은 저장 후 다시 표시되지 않고 AI에게 전달되지 않습니다")만 보면 참가자는 "이 값은 안전하다"로 읽는다. 화면에서 쓰는 값은 방문자에게도 보일 수 있고 관리 책임은 참가자에게 있다는 안내가 필요하다. 문구는 기획에서 잡아주면 된다
- **고정 범위를 벗어난 앱의 동작.** 참가자가 다른 방식으로 앱을 만든 경우 기능을 숨길지, "값이 전달되지 않을 수 있다"고 알릴지

### 3. 팀을 전제로 다시 설계한다

기획 §4에 팀 얘기가 한 줄도 없고 시안도 전부 1인팀(C-3)이다. 그런데 이 제품에서 다인팀은 곁다리가 아니다. 키 입력창은 **팀원 전원 화면에 뜬다.** 지금 정의로는 그중 누가 채우는지, 두 명이 서로 다른 값을 넣으면 무엇이 저장되는지, 한 명이 취소하면 어떻게 되는지가 전부 미정이다.

값 교체와 삭제는 더 심각하다. 되돌릴 수 없고(원래 값을 아무도 모른다) 틀리면 앱 전체가 죽는다. 이 제품은 메시지 하나 보내는 데도 전원 동의를 받는데(E-4 v3 전송 동의), 그보다 파괴적인 동작이 아무 게이트 없이 열려 있다.

**제안은 두 가지다.**

**이름과 값을 함께 공동 편집한다.** 질문 도크의 직접 답변과 같은 방식이다. "누가 채우느냐"를 규칙으로 정하려 하지 말고 같이 채우게 하면 그 질문 자체가 사라진다. 전원이 보는 앞에서 채우니 몰래 넣는 일도 없다.

**확정에는 동의를 받는다.** 저장·교체·삭제 모두 되돌릴 수 없으므로 확정 시점에 전원 동의를 거친다. 기존 전송 동의 흐름을 재사용하되, 스냅샷에 값을 보여줄 수 없으니 어떤 연결에 무슨 동작을 하는지까지만 표시한다. 1인팀에서는 동의 절차 없이 바로 확정한다.

딸려오는 카피 변경이 하나 있다. 공동 편집이면 값이 팀원 전원에게 보이므로, 현재 문구 "이 값은 AI에게 전달되지 않아요" 옆에 **"팀원 모두에게 보입니다"**가 함께 있어야 한다. 개인 유료 키를 넣는 참가자에게 필요한 안내다.

> 값이 오가는 경로는 확인했다. 질문 초안은 메모리와 웹소켓 중계로만 존재하고 디스크에 남지 않으므로, 공동 편집으로 바꿔도 "AI에게 전달되지 않는다"는 계약은 유지된다. 관전자 배제와 저장 후 초안 폐기는 개발에서 처리한다.

## 개발이 정하고 알리는 것 (결정 요청 아님)

- **기본 스택 고정.** §1.2 실측상 참가자 앱 다수가 단일 페이지 클라이언트였으므로 그 형태에 맞춰 고른다
- **이름 규칙.** 화면에서 쓸 값은 접두사가 있어야 브라우저로 간다(vite면 `VITE_`). 없으면 서버 프로세스까지만 들어가고 화면에서는 빈 값이다. **이 접두사가 관리 화면의 이름에 그대로 보이므로 공유한다** — §3.5 "이름은 앱이 자동으로 정한다"와 "값 필요" 줄 이름이 모두 이 규칙을 따른다
- **개발 서버 실행 위치를 프로젝트 루트로 고정.** 현재는 AI가 실행 디렉터리를 자유롭게 넘길 수 있어(`ensure_dev_server` 의 `cwd`), 하위 폴더에서 서버를 띄우면 파일 위치가 어긋나 에러 없이 값이 비어 있다
